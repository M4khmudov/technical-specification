# Technical Specification — свечная мастерская

Мини-система учёта склада и производства для мастерской ароматических свечей
и ИИ-ассистент поверх неё.

## Запуск

```bash
cp .env.example .env   # при необходимости вписать OPENAI_API_KEY
docker compose up -d --build
```

| Сервис | Адрес |
| --- | --- |
| Интерфейс | http://localhost:3000 |
| API и OpenAPI | http://localhost:8000/docs |
| Мок внешних сервисов | http://localhost:8001 |
| PostgreSQL (снаружи) | localhost:5433 |

Миграции применяются автоматически при старте бэкенда.

## Тесты и линтеры

```bash
docker compose exec backend pytest
docker compose exec backend ruff check .
cd frontend && npm run lint
```

Тесты идут на настоящем PostgreSQL в отдельной базе `candles_test`; схема
создаётся теми же миграциями Alembic. LLM в тестах — заглушка, в сеть тесты не ходят.

## Стек и решения

- **Бэкенд:** Python 3.12, FastAPI, SQLAlchemy 2 (async, asyncpg), Pydantic v2, Alembic.
- **Фоновые задачи:** arq + Redis. Выбран вместо Celery, потому что он асинхронный,
  как и весь бэкенд, и не требует отдельного брокера/бэкенда результатов.
- **Фронтенд:** React + TypeScript (Vite), Tailwind. В Docker раздаётся nginx,
  который проксирует `/api` на бэкенд без буферизации (нужно для SSE).
- **Мок-сервисы** (курсы валют, сервис маркировки) — отдельный контейнер `mocks`.
- **Ключи** только из переменных окружения, в репозитории лежит `.env.example`.
- Имя compose-проекта задано явно (`name: candles`), потому что имя папки может быть
  не латиницей.
